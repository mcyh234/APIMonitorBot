# 新闻总结与事件记忆

总结是 AI 消息监听的附加模块，默认关闭。更新后先安装 `requirements.txt` 的依赖，再重启服务；数据库会自动创建两张独立的新表，无需手工迁移现有监听状态。

## 从聊天开启

以下命令仅限 Bot 管理员，各自受 WebUI 命令开关控制。

```text
/summarymodel list
/summarymodel 3
/newssummary count 10
/newssummary on
/newssummary status
```

`/summarymodel` 的参数支持监测配置 ID、完整配置名称、`list`、`status` 和 `default`。它只保存配置 ID，实时复用其模型、加密密钥、协议和 TLS 设置，不复制或显示凭据。`default` 跟随当前审核模型；没有可用审核模型时总结暂停。停用或删除所选配置后不会静默切换模型。使用 `/newssummary off` 关闭功能，`/summarymodel off` 会给出正确命令提示。

## 计数与触发

每个 `G群号` 或 `PQQ号` 独立累计**成功确认送达**的自动新闻；一个帖子在一个对象只计一次。首次开启不回放过去的新闻。失败发送、重复读取、手动 `/tibo` 和总结图片不计数，因此不会递归生成总结。

- `count 1–100`：条数阈值，默认 10。已排队的批次保留原先的新闻范围，修改值用于后续批次。
- `wait 0–1440`：未满条数时，从本轮最早送达新闻开始计算的最长等待分钟数；0 表示只按条数触发。
- `now G群号` / `now PQQ号`：提前总结已有新闻；若已有任务则立即重试。省略目标时使用当前群或管理员当前私聊对象，目标必须已订阅 AI 消息监听。
- `on/off`：开启或暂停；暂停期间不收集新总结素材，原有待总结项保留。AI 消息监听关闭时，总结也暂停投递。

后台每 15 秒检查一次，每轮最多处理两个对象的总结，单个对象同时只保留一个活动批次。生成、审核和重试都独立于普通新闻流程，期间原始新闻继续推送；总结完成后追加图片，不承诺恰好紧跟第 N 条消息。

原始新闻的计数与其发送确认在同一事务中保存。批次来源冻结，分页发送分别确认，重启后只继续未确认的页面。模型、配置、记忆或订阅变化会使在途结果失效；部分页面已经发送后发生变化时取消剩余页，避免拼接两版总结。OneBot 已接收而 SQLite 尚未保存确认的极短崩溃窗口仍可能导致最后一页重复。

## Markdown 与事件时间线

图片使用统一 Material 日夜主题、中文字体和离线 Twemoji，无需浏览器、外部字体服务或图片下载。支持标题、加粗、强调、删除线、嵌套列表、引用、表格、行内代码和代码块。长文分页，最多 8 页；外部图片和模型生成的外部链接不会进入报告。

每条本期新闻分配 `N1`、`N2` 等引用，历史新闻使用 `M记录ID`。总结必须覆盖本期全部来源，虚构、缺失或跨对象的引用会被拒绝。报告自动附来源索引与真实 X 链接，不依赖模型编造链接。

时间线由大模型按事件组织节点，应用使用引用来源的真实时间排序并渲染；没有发布时间时标注“送达时间”。本期、历史和混合引用分别标记。历史关联支持“进展、补充、对比、可能相关”，不把共同公司名直接当作因果关系。没有可靠证据时可以不生成时间线或关联。

```text
/newssummary timeline on
/newssummary connections on
/newssummary wait 120
```

WebUI 还支持简洁/标准/详细模式和关注主题。图片预览、Markdown 原文及导出位于“总结历史”。Markdown 下载包含时间线、历史关联和来源引用，便于归档与分享。

## 记忆与隔离

记忆仅来自同一通知对象成功总结过的已审核新闻，不收集普通群聊，也不借用其他群或私聊的新闻。原文和译文各保存最多 3000 字符的加密片段；生成时再按总上下文预算提取片段，模型无法据此获知全文中未提供的细节。

检索使用本地产品名、技术词及中英文关键词匹配，从近期历史中选取相关片段交给总结模型；这是新闻库检索，不是模型训练或联网搜索。默认保留 30 天、每对象最多 300 条、每次检索最多 12 条。WebUI 可调整为 1–365 天、10–1000 条记忆和 1–30 条上下文。

```text
/newssummary memory on
/newssummary days 30
/newssummary clear G123456789
/newssummary history
```

“清空本对象历史记忆”删除该对象的已处理新闻片段和历史总结正文，保留待总结的新帖，并使旧记忆参与的在途结果失效。关闭记忆会清理全部历史正文；功能仍可基于本批新闻生成总结，但不保留其长期正文。移除通知对象会清理其所有总结数据，移除账号会清理对应素材及受影响的活动批次。

每个对象最多积压 2000 条未归入批次的素材，最多保留 200 条历史批次元数据。超过容量会清理最早素材，超过保留期限的未总结素材也不再使用；原始新闻监听的待发送队列不受此清理影响。损坏、过期或被当前本地规则拦截的历史片段不会进入检索结果。

## 审核、失败与排查

总结输入先经过本地过滤，输出及引用片段再由审核模型统一检查。审核模型缺失、超时、响应无效或不确定时不能发送；审核还会检查无依据的事实、时间和关联。明确拦截的总结删除正文，只保留固定分类原因、时间与计数等元数据，不保存模型自由文本。

模型、审核或发送服务异常会保留加密任务，按 60 秒起的指数退避重试，最长一小时；WebUI 显示下次重试和已投递页数，可手动提前重试。功能无法保证模型推断完全正确，也不能保证通过所有法律或平台审核；实际发送仍受不可关闭的严格过滤控制。

WebUI 的状态页区分：模型不可用、监听暂停、当前累计、活动批次、失败重试、审核拦截和已送达历史。所有新增 API 都要求 WebUI 登录，历史正文只通过鉴权接口按需解密。发送审计只保存图片短预览。

## 离线验收

`scripts/render_theme_samples.py` 生成 `news-summary-light-1.png` 与 `news-summary-dark-1.png` 等示例，包含表格、代码、emoji、历史节点与关联。`scripts/preview_monitor.py` 与 `scripts/smoke_monitor_ui.cjs` 覆盖设置、模型选择、手动排队、记忆检索、图片预览、Markdown 导出、手机布局、键盘关闭和鉴权边界。全部使用明确标注的离线示例，不启动总结定时任务，不连接真实 OneBot。
